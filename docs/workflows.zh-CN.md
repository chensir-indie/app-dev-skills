# 工作流与交接

[English](workflows.md) · [选择技能](../README.zh-CN.md#选择技能)

按用户手头的材料和要求的终点选择。推荐、执行或排除某个分支前，读取对应 `SKILL.md`；名称和摘要只用于导航。沿用已有授权，保留项目中可用的文件。

## 选择交付终点

| 用户需求 | 入口与第一步 | 完成信号 |
| --- | --- | --- |
| 探索设计方向或编写图片提示词 | [Image to Layered HTML Prototype](../skills/image-to-layered-html-prototype/SKILL.md)：进入概念/提示词分支 | 所需方向或提示词、约束和选择依据。仅在要求图片时生成图片；HTML 是另一个终点 |
| 还原已认可图片 | [Image to Layered HTML Prototype](../skills/image-to-layered-html-prototype/SKILL.md)：冻结参考身份，建立页面/状态合同 | 可编辑页面与素材、manifest、浏览器截图、要求的对比和真实剩余差距 |
| 修复现有分层页面 | 同一技能：先盘点当前 HTML 和素材，再界定修复范围 | 对照保留的参考和合同验证修改区域/状态，保留未受影响的结构 |
| 制作或调整商店封面 | [App Store Cover Generator](../skills/app-store-cover-generator/SKILL.md)：区分新建项目与现有矩阵，先检查源码和配置 | 从可编辑源码导出要求的矩阵单元，记录布局/本地化检查，并对照最终哈希完成视觉审查 |

此前任务提供的研究可以支持设计方向，它是这两个技能的输入。有限证据不能代替缺失的截图、测量或审查。明确说明完成的是哪个分支，以及它的限制。

## 阶段之间传递什么

在现有报告或项目中保留简短交接记录。引用文件，避免整份复制内容：

```text
下一步要求的结果：
产物路径与身份/哈希（文件已冻结时）：
来源、版本/日期、视口和交互状态（适用时）：
观察事实 / 来源声明 / 推断 / 未知：
已完成检查与证据文件：
剩余差距与下一项具体动作：
```

已有 schema 与状态字段仍是权威定义。交接记录用于定位证据，不新增审批步骤，也不替代 manifest。

| 阶段转换 | 带入下阶段 | 进入条件 |
| --- | --- | --- |
| 外部研究 → 设计方向 | 报告、证据链接、产品约束、优先机会及未知项 | 在用户范围内选定设计问题；研究推断继续标为推断 |
| 设计方向 → 分层还原 | 选定参考及哈希、页面/状态、尺寸、素材/字体和验收标准 | 只要提示词时到此结束；完整还原中缺参考或素材时保留约束 |
| 分层原型 → App 实现 | 可编辑源码、设计合同、对比结果和已知差距 | 在产品仓库实现并做设备验证；原型通过不能证明这些步骤已完成 |
| 已实现 App → 商店封面 | 实际 App 截图、已知的 App/构建身份、有证据的卖点、语言/设备/页面计划 | 标注示例/概念素材；产品声明及基于截图的交付使用真实产品证据 |
| 封面导出 → 商店流程 | 精确 PNG、矩阵、哈希、联系表和审查记录 | 上传/提交属于另行授权的任务并须核对平台状态；导出保持为导出状态 |

已有项目从当前阶段进入，不能为了走完整流程而从模板重建。

## 缺少能力时

在即将执行依赖脚本之前运行该技能对应范围的 `doctor.sh`。概念或阅读任务无须先装齐全部渲染环境，安装与修复见[环境支持](runtime.zh-CN.md)。

继续独立工作，依赖失败工具的步骤保持待完成。说明缺少的运行时/包/浏览器、修复命令和重跑检查。替代工具须能提供所选合同要求的证据，不能把缺失检查写成假定通过。
