# 工作流边界

[English](workflows.md)

修改技能的职责或交接方式时，请参考本页。选择和使用技能可直接查看[技能表](../README.zh-CN.md#如何使用)。

| 技能 | 默认交付内容 | 范围限制 |
| --- | --- | --- |
| 竞品分析 | 附有证据的报告与产品建议 | 标明推断。完成分析并不代表设计方案已获批准。 |
| 分层 HTML | 可编辑页面与浏览器对比 | 只做概念设计或评审时，可以提前结束。原型截图和真实应用截图要分别标明。 |
| iPhone Duo | 分析整个应用的布局，提出建议，再制作完整 HTML 原型 | 用户明确只要建议时，在该阶段结束。原生实现和真机验收是后续独立阶段。 |
| 商店封面 | 可编辑源码，以及逐一审查过的各语言、设备和页面导出图 | 获准导出不包含上传授权。 |
| 应用发布 | 用户指定的本地或平台阶段 | 上传 TestFlight 时，取得对应文件、版本和构建号的成功回执后结束。处理、分发、审核和公开发布需分别验证。 |

具体步骤和验收要求以对应的 `SKILL.md` 为准。交给下一阶段时，应提供已有文件的路径和哈希、来源及当前状态、已完成的检查和待解决的问题，并区分亲自观察到的结果与推断。沿用已有决策和授权，交接时不另加审批环节。

Duo 的完整规则目录、实现前的交接材料、项目约定和浏览器证据，都应遵循[工作区规则要求](../skills/iphone-duo-adaptation/references/workspace-rules.md)。本合集的记录用于验证技能维护；目标应用是否通过验收，需要它自己的证据。
