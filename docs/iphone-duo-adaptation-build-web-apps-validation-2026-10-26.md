## Evaluation design and isolation

The original synthetic Pocket Notes fixture contains Notes, Detail, Edit/New, Search, Settings and Delete confirmation, with blue branding and two original notes. Its supplied manifests describe a Capacitor/WKWebView shell; these declarations are not a compiled native app or installed-toolchain result. The runnable current UI is original HTML. This is not real IMX, customer data, or a product-device capture.

The parent froze input and candidate Skill hashes plus an independent page/task/process/negative-check acceptance list before the generating Agent ran. The realistic request did not supply an implementation or expected layout. Outputs are isolated from the collection and product repositories, with no installations, account actions or publication. The inherited model configuration had no model/reasoning override; the evaluator interface does not expose a verified exact model identifier.

The first attempt disclosed a quick workflow-memory lookup during baseline work. It was interrupted before prototype construction and archived rather than counted as an isolated complete run. A new Agent with no inherited chat was then given only the raw fixture, current Skill, actual upstream contracts and available tools, with memory, prior outputs and the parent's review directory explicitly excluded. A late source-research child of the discarded attempt wrote three advisory files to the reused workspace path; they were quarantined. The new generator disclosed seeing their filenames only, without opening/using their contents, and had independently fetched its own primary-source texts. Those independently fetched files were retained. Both the discarded attempt and isolation audit remain recorded.

The clean run captured 24 original-layout screenshots, wrote its baseline/recommendations/coverage, and generated primary expanded, narrow-list and editor concepts. It rejected a concept that changed the required heading from “All Notes” to “Notes” and regenerated it before coding. The design handoff and accepted concept hashes were frozen at 02:44:51 UTC; prototype files were first created at 02:46:19 UTC. Parent observations independently recorded baseline/design artifacts before prototype HTML existed.

The actual prototype was also opened in the in-app browser. Selection, editor entry, cancellation, preserved saved content and return navigation were observed through the rendered accessibility tree. This is browser/AX evidence, not a VoiceOver task result.

Independent candidate testing found material defects before final acceptance: long single-paragraph reflow moved the visible reading location by 2,047 words on narrow-to-wide resize, and 200% text clipped the Settings destination at 390px width. Parent in-app-browser interaction also found that the skip link's `#workspace` fragment collided with hash routing and discarded an open edit draft. These went back to the generator for repair and direct regression checks. A suspected native-dialog Tab-wrap failure was instead reproduced in a minimal Chrome dialog and removed as a test overconstraint: neutral document/browser-boundary focus must not be confused with focus reaching background app controls. The generator chose to strengthen its stated modal-containment behavior separately, retaining Escape/close; this is an intentional enhancement rather than evidence of a Chrome defect. Original failure/probe evidence is retained.

The process audit also found that initial rule bindings and project conventions were filled after preliminary implementation, despite the stage-2 handoff requirement. This was not backdated or relabeled as an initially complete handoff. The generator recorded the deviation, completed the 66-rule/10-convention attribution, froze that completed handoff at 03:01:47 UTC, reviewed the preliminary implementation against it, and re-entered the final construction/render/QA iteration. The original design freeze remains unchanged. This demonstrates a remediated execution, not flawless first-pass adherence.
